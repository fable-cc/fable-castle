# fable-castle 自站 GEO 修复案例页设计

日期：2026-07-28
状态：待用户书面规格确认后实施
目标页面：`/cases/`

## 1. 背景

当前 `/cases/` 页面已有两个泛样板案例，但存在两个问题：

1. 案例不是围绕 `fable-castle.com` 自身修复展开，证据冲击力不足。
2. 页面含有未附原始证据的数据表达，例如“AI 搜索可见率 0/10 → 6/10”，容易被客户或 AI 系统判断为不可复核承诺。

本站当前定位已经从泛知识库/课程站，收束为“创始人 AI 可见度与 IP 资产诊断站”。因此案例页也应服务同一主线：展示一次真实、可复核、有边界的 GEO 修复过程。

## 2. 设计目标

把 `/cases/` 改造成一个高信任案例页：

- 主案例使用本站自身：`fable-castle.com`。
- 案例主题为：从“AI 不易识别 / 旧入口噪音 / 同名主体混淆 / 抓取策略不清”，修复到“主入口清晰 / AI 索引文件权威 / 技术可抓取 / GitHub 证据链可复核”。
- 所有结论必须有证据口径，不写无法验证的排名承诺、引用承诺或提升百分比。
- 页面最终转化到 `/diagnosis/`，不出现低价课、旧课程、旧知识库主入口。

## 3. 页面定位

页面标题建议：

`案例：fable-castle.com 从 AI 不易识别到可被验证的 GEO 修复`

页面一句话：

`这不是“保证 AI 推荐”的案例，而是一次公开站点如何被整理成可抓取、可理解、可验证、可持续监测的 GEO 修复记录。`

## 4. 信息架构

页面分为 8 个区块。

### 4.1 Hero 区

内容：

- 标题：案例：fable-castle.com 的 GEO 修复记录
- 副标题：从旧内容噪音、主体混淆和爬虫策略不清，到一个更清晰的创始人 AI 可见度诊断站。
- 标签：
  - 自站案例
  - GEO 修复
  - AI 可见度
  - 可复核证据
- 主按钮：预约 AI 可见度诊断 → `/diagnosis/`
- 次按钮：查看 GitHub 证据链 → `/github-trust/`

### 4.2 修复前问题

用卡片列出修复前的核心问题：

- 主叙事分散：旧课程、知识库、方法论、工具、服务混在一起。
- 主体识别不稳：需要持续强化“景一 fable / fable-cc / 景一的寓言城堡”的一致身份。
- 旧入口噪音：低价课程、旧知识库、课程目录容易稀释高客单服务定位。
- AI 文件过期：`llms-full.txt` 曾包含旧业务线、价格和知识星球等过期叙事。
- 抓取策略不清：Cloudflare AI bot policy 与 `robots.txt` 需要统一。

注意：不写“搜索排名提升”“AI 引用提升”这类未经当前公开证据支撑的结果。

### 4.3 五维诊断

以五维模型呈现：

| 维度 | 修复前问题 | 修复动作 |
|---|---|---|
| 定位资产 | 主页与旧入口容易让外界误读为课程/知识库站 | 统一为 GEO 与创始人 AI 可见度诊断站 |
| 内容资产 | 内容多但主线不够收束 | 保留指南、研究、工具、案例，旧素材退出正式构建 |
| 信任资产 | GitHub 仓库多但层级不清 | 建立 `/github-trust/`，A/B/C/D 分层 |
| 搜索资产 | Sitemap 推送旧入口 | Sitemap 收束到核心页面 |
| AI 可见度资产 | `llms-full.txt` 过期、AI 爬虫策略不统一 | 重写 AI 索引说明，调整 robots 与 Cloudflare 策略 |

### 4.4 执行动作时间线

用时间线或步骤列表展示已完成动作：

1. 统一主入口：主页与导航指向 `/diagnosis/`。
2. 清理低价课入口：服务页不再出现免费课/低价课主入口。
3. 修复身份命名：统一为“景一 / 景一 fable / fable-cc / 景一的寓言城堡”。
4. 建立 GitHub 信任页：公开仓库按 A/B/C/D 分层说明。
5. 重写 `llms-full.txt`：只保留当前权威叙事、服务边界和核心 URL。
6. 收束 `sitemap.xml`：旧课程、旧知识库、旧方法论不再作为核心 URL 推荐。
7. 增强 `robots.txt`：允许搜索/问答爬虫访问核心公开页，同时对旧路径降噪。
8. 增加 CI 防回流：旧入口若重新进入 `_site` 或 AI 索引文件，构建失败。

### 4.6 修复结果

用稳健措辞：

- 当前站点从“内容资产很多但对外叙事分散”，升级为“以诊断为主入口的 GEO 顾问站”。
- AI 和搜索引擎看到的权威文件更清晰：`llms.txt`、`llms-full.txt`、`sitemap.xml`、`robots.txt` 口径一致。
- 客户看到的转化路径更短：先诊断，再按短板进入服务。
- 旧素材仍保留在仓库中，但不再作为官网主入口干扰判断。

不得写：

- “AI 可见度提升到 100 分”
- “保证被 ChatGPT / DeepSeek / Kimi 引用”
- “Google / 百度一定收录”
- “排名提升 X%”

## 5. 视觉与语气

视觉保持当前“证据型思想领袖”风格：

- 暖白底色
- 报告式卡片
- 克制蓝色/金色强调
- 少用营销大词
- 多用“证据、边界、动作、复核”

语气：

- 不神化 GEO。
- 不承诺不可控结果。
- 强调“这是一套让 AI 更容易识别和引用的基础设施修复”。

## 6. 技术设计

直接更新 `cases/index.html`，保持静态页面，不引入新依赖。

必须包含：

- `sitemap: true`
- canonical：`https://fable-castle.com/cases/`
- title 与 description 使用“景一的寓言城堡”
- JSON-LD：
  - `CollectionPage`
  - `Person`
  - `CaseStudy` 可用 `CreativeWork` 表达，因为 Schema.org 没有通用 `CaseStudy` 类型
- 导航与其他页面一致：
  - 工具
  - 研究
  - 案例
  - 服务
  - 关于
- 所有链接使用当前正式 URL。

## 8. 风险与处理

### 风险：把自站修复写成自吹

处理：用“问题 → 动作 → 可复核证据 → 边界”结构，不写夸大成效。

### 风险：用户误解为保证 AI 引用

处理：页面明确写“不承诺排名、收录或 AI 引用，只证明基础设施和证据链更清晰”。

### 风险：旧入口仍被外部索引访问

处理：旧入口保留 404/robots 降噪；如后续有高价值历史外链，再单独设计 301 策略。

## 9. 不做范围

- 新建动态案例系统。
- 接入数据库。
- 添加客户表单。
- 发布未经授权的真实客户案例。
- 生成排名、引用率、增长率等未复核数据。
- 修改 Cloudflare 设置。
